# Annotating

An **annotation** says what a data point means: a name ("Watched videos"), a description, an
optional note for other curators, and whether it is **personal information (PII)**, meaning it
can identify a person, like an email address or a username.

You can annotate from a platform's [explorer](exploring.md) or an upload's
[review](reviewing.md): select a data point, then **Add annotation** in the side panel. You need an
account.

## What gets annotated

A **data point** is anything that carries meaning of its own:

- a **value**, like a date, a name or a count;
- a **list**, and each **entry** in it: in a list of watched videos, the entry is "a watched
  video" and carries the meaning; its fields (date, link) are data points of their own;
- a **media file**, like a photo or a video.

Objects that only group other fields, folders, and the archive itself aren't data points: they
only tell where the data lies.

A list and its entry are annotated one after the other: first the entry ("Watched video"), then
the list, whose name is suggested for you ("List of Watched video").

## The annotation dialog

The dialog opens next to the side panel, so you can keep reading while you annotate. For a data
point it offers:

- **Likely matches**: if the data point was probably moved or renamed, the earlier field's
  annotation, one click away;
- **New annotation**: name, description, note, PII;
- **Existing annotations** of the platform, searchable, to link to;
- **Not a data point**, for things that don't need a description.

One annotation can cover several places: the same data point often sits at a different path in
another export version, or has another name in another language.

## Examples

Examples show what a data point's values look like. If you uploaded the DDP, the side panel shows
the values from **your** file (only to you). Once the data point is annotated, you can choose some
of them to add to its public examples. They are added exactly as they are; nothing becomes public
until you do this. Curators can also type examples by hand.

## Suggestions

**Staff** decide what is annotated. If you aren't staff, the same buttons read "Suggest …", and
your change becomes a **suggestion** that waits for staff: a new or edited annotation, linking or
unlinking a data point, marking it as not a data point, or anything about
[representations](representations.md).

- Open suggestions are visible to everyone: a data point shows "1 suggestion", and counts as still
  to do until it is decided.
- Staff **accept** (the change applies, in your name) or **reject** (with a reason for you) each
  suggestion. If several people suggested something for the same data point, accepting one
  replaces the others.
- **My suggestions** in the top menu lists yours and how they were decided. You can withdraw an
  open one, and a newer suggestion of yours for the same data point replaces your older one.
